# Animation (Runtime + AnimGraph) — Architecture Audit

> Re-audit pass. Original audit was written at commit `d714482` ("Audit"). This pass compares that
> baseline against `HEAD` to determine which findings are fixed. Important caveat discovered during
> this pass: commit `d714482` itself already *bundled* several small fixes alongside the act of
> writing the original `AUDIT.md` — those fixes are only visible by diffing `d714482^` (its parent)
> against `HEAD`, not `d714482` against `HEAD`. `git diff d714482 HEAD -- Runtime/Animation/
> Editor/Animation/` shows almost nothing (see below) precisely because those fixes already existed at
> both ends of that range. This document reports true current status against the findings as written,
> not just what changed since `d714482`.

## Context

Scope re-audited: same as the original — `Runtime/Animation/` (incl. `AnimGraph/` subfolder),
`Editor/Animation/`, `Editor/AnimGraph/`. This pass re-read every file that had any finding against it,
plus diffed the full ranges `d714482^..d714482` and `d714482..HEAD` for the scope to separate
"fixed inside the audit commit itself" from "fixed afterward" from "not fixed".

Verified directly: `AnimatorBridgeBase.cs`, `PlayableGraphBridge.cs`, `MixerStates.cs`, and
`PlayableState.cs` (the four files carrying the confirmed optional-parameter violations) — checked both
via `git diff` and by reading current line content.

## What actually changed since the original audit was written

- `git diff d714482 HEAD -- Runtime/Animation/ Editor/Animation/` — **one line, one file**:
  `Editor/Animation/AnimationSetCodeGenerator.cs`'s `OutputFolder` constant was repointed from
  `Assets/Frameworks/CharacterSystem/Runtime/AutoGenerated/AnimationSets` to
  `Assets/Scripts/AutoGenerated/AnimationSets`. This is an unrelated build/output-path config change
  (the old `Assets/Frameworks/CharacterSystem/...` destination presumably no longer exists after a
  project reorg elsewhere in the main repo) — it has nothing to do with any finding below.
- Diffing `d714482^..d714482` (i.e. what landed *inside* the same commit that introduced the original
  `AUDIT.md`, before this comparison's nominal baseline) shows the audit author already fixed four
  small items while writing the audit, without updating the audit text to say so:
  - `PlayableState.cs`: `Events(object owner = null)` → `Events()` — the dead `owner` parameter was
    dropped entirely (all five call sites in `AnimatorBridgeBase.cs` updated from `state.Events(this)`
    to `state.Events()`).
  - `AnimatorBridgeBase.cs` and `AnimGraph/AnimationSetSequenceUtility.cs`: the duplicated private
    `FindEntryById(set, id) => set.FindEntry(id)` forwarder was deleted from both files; all call sites
    now call `set?.FindEntry(entryId)` directly.
  - `Documentation~/ARCHITECTURE.md`'s "## Animation" section was rewritten from a 4-row stub into a
    comprehensive table covering `AnimatorBridgeBase`, the full `PlayableState` family, `PlayableLayer`,
    `ILocomotionBlendLayer`, `AnimationSetValidationProfile`, `AnimationEventCatalog`/`CoreAnimationEvents`,
    `CrossfadeSourceMode`, etc.
  - `Documentation~/PlayableGraphBridge-Invariants.md` was created (27 lines, promoted from the inline
    comments in `PlayableGraphBridge.cs`), and the `ARCHITECTURE.md` row for `PlayableGraphBridge` now
    links to it instead of pointing at a non-existent doc.
- Outside the assigned scope but touching a file this audit cross-referenced: between `d714482` and
  `HEAD`, `Runtime/Extensions/Animations/AnimatorExtensions.cs` had its three optional-parameter methods
  (`GetCrossFadeProgress`, `WaitForCurrentStateToFinish`, `WaitForStateToFinish`) converted to the
  explicit-overload pattern (mirrors `AUDIT.md`'s own recommended fix), and
  `Runtime/Extensions/Animations/FadeExtensions.cs`'s `FadeCanvasGroup` got the same treatment. Neither
  file is in this package's Animation scope, and neither changes the `Animator.GetCurrentAnimatorStateInfo`
  calls that were the actual cross-reference concern (those calls are untouched, still present at the
  same lines) — so the underlying cross-reference finding is unaffected even though the optional-param
  style in that file improved.

## Findings — status of each original item

### Consumption Contract / Animator Boundary

- **No longer applicable / unchanged — still no findings.** `AnimatorBridgeBase` still never calls
  `Animator.GetCurrentAnimatorStateInfo`/`GetAnimatorTransitionInfo`. Confirmed by direct grep of the
  current file: zero hits.
- **Not fixed (informational, no fix expected)** — `TryGetCurrentSetAndEntry` (now `AnimatorBridgeBase.cs:564`,
  shifted from `:570` after the `FindEntryById` deletions above) is unchanged: still `public virtual`,
  still a legitimate but ungated reverse-lookup. This was flagged as a watch item, not a defect requiring
  a code change, so "not fixed" here just means it remains exactly as described — no regression, no
  remediation needed unless a caller actually misuses it.
- **Not fixed (out of scope, unchanged)** — `Runtime/Extensions/Animations/AnimatorExtensions.cs` and
  `SyncAnimatorTime.cs` still call `Animator.GetCurrentAnimatorStateInfo` directly at the same call sites
  (`SyncAnimatorTime.cs` has zero diff since the original audit's baseline). Still a watch item for a
  future `Runtime/Extensions/` audit, not this package's scope.

### Data/Controller/View Boundary

**Unchanged — still no findings.** Nothing in this pass' re-read of `AnimationSet`/`AnimatorBridgeBase`/
`PlayableGraphBridge` introduced simulation-state ownership.

### Ownership

- **Not fixed.** The dual Playables-graph-vs-Mecanim-`AnimatorController` ownership question is untouched:
  `git diff d714482 HEAD -- Editor/Animation/AnimatorConstantsGenerator.cs` is empty, and
  `git diff d714482^ HEAD` for the same file is also empty — this file has not been touched at all since

- No findings otherwise — unchanged.

### Designer Surface Priority

**Unchanged — still good compliance, no findings.**

### Redundancy/Simplification

- **Error — still Not fixed.** 8 of the original 9 optional-parameter violations remain, byte-for-byte
  identical to the original audit (only line numbers shifted slightly due to the `FindEntryById`
  deletions):
  - `AnimatorBridgeBase.cs:391` — `PlayFromPlayableAnimationSetEntry(..., float startNormalizedTime = 0f)` (private)
  - `AnimatorBridgeBase.cs:591-592` — `public virtual IEnumerator CrossfadeAsync(AnimationClip clip, AnimationClipInfo clipInfo, AnimationMask mask, ActionData[] actions = null, int layerIndex = -1, bool transitionBack = true)`
  - `AnimatorBridgeBase.cs:623` — `public virtual void PlayLoopingAnimation(AnimationClip clip, AnimationMask mask, bool isActAsAnimatorOutput = false, float transitionIn = 0.1f)`
  - `PlayableGraphBridge.cs:37` — `public void InitializeGraph(Animator animator, int initialLayerCount = 3)`
  - `PlayableGraphBridge.cs:179` — `public ClipState Play(ClipTransitionData transition, float fadeDuration = -1f)`
  - `PlayableGraphBridge.cs:209` — `public ClipState Play(AnimationClip clip, float fadeDuration = 0.25f)`
  - `PlayableGraphBridge.cs:215` — `public PlayableState Play(PlayableState state, float fadeDuration = 0.25f)`
  - `MixerStates.cs:14,67,75,125` — `MixerState`/`ManualMixerState`/`LinearMixerState`/`DirectionalMixerState` constructors, `int childCount = 0`

  None of these have been converted to the explicit-overload pattern the codebase prescribes and that
  this same package uses correctly elsewhere (`PlayFromSetStrict`, still at two explicit overloads,
  unchanged). Note the irony: `Runtime/Extensions/Animations/AnimatorExtensions.cs` — a file this same
  `AUDIT.md` only cited as an out-of-scope *cross-reference* — received exactly this fix pattern after
  the audit was written (see above), while the in-scope, explicitly-flagged violations listed here did
  not.

- **Fixed.** `PlayableState.Events(object owner = null)` (previously `PlayableState.cs:64`, still line 64)
  had its unused `owner` parameter dropped entirely — it is now `public PlayableStateEvents Events()`.
  All five call sites in `AnimatorBridgeBase.cs` (`:612` and others) were updated from `state.Events(this)`/
  `.Events(this)` to `state.Events()`. This matches the audit's own recommended remediation ("drop or wire
  up the unused parameter") — they chose to drop it. Note this fix landed inside commit `d714482` itself,
  before the `AUDIT.md` describing it as still-open was committed in that same commit — the text was
  simply never updated to match.

- **Fixed.** The duplicated private `FindEntryById(AnimationSet, string)` forwarder is gone. Both copies
  (`AnimatorBridgeBase.cs:197-201` and `AnimationSetSequenceUtility.cs:181-185` in the original audit) were
  deleted; every call site now calls `set?.FindEntry(entryId)` directly, exactly as the audit suggested
  ("`AnimationSet.FindEntry` could be called directly at both sites"). Also landed inside commit `d714482`
  itself.

## Fixes

No source files were modified by this audit pass — read-only, as instructed. Status of the original
remediation list:

1. ~~Replace the optional parameters... with explicit overloads~~ — **not done** for any of the 8
   remaining violations in `AnimatorBridgeBase.cs`/`PlayableGraphBridge.cs`/`MixerStates.cs`. Still the
   top open item; still recommend starting with the `public`/`public virtual` members
   (`CrossfadeAsync`, `PlayLoopingAnimation`, `InitializeGraph`, the three `PlayableGraphBridge.Play`
   overloads) since those are the widest-reaching call sites.
2. Decide and document the `AnimatorConstantsGenerator` vs. Playables-graph ownership question — **not
   done**. Still open, still no decision recorded anywhere in this scope.
3. Refresh `ARCHITECTURE.md`'s Animation section / write or fix the invariants-doc pointer — **done**.
   Both halves of this recommendation landed (inside commit `d714482`, concurrently with the audit's own
   writing, though the audit text wasn't updated to reflect it at the time).
4. Drop or wire up the unused `owner` parameter on `PlayableState.Events` — **done** (dropped).

Remaining open work, in priority order:

1. Convert the 8 remaining optional-parameter violations to explicit overloads.
2. Make and document the `AnimatorConstantsGenerator` ownership decision.
3. (Low priority, no fix required) Continue treating `TryGetCurrentSetAndEntry` and the
   `onComplete`/`OnEnd`-callback determinism boundary as watch items for consumer audits.
4. (Low priority) Fix the `Awake()` ref-caching inconsistency (guard `animator` the same way `animancer`
   is guarded, or intentionally document why it's reassigned unconditionally).
